결함 패턴 분류

웨이퍼맵 이미지 17만 장을 먼저 EDA로 하나하나 들여다본 뒤, 특정 결함 패턴이 없는 none 1종과 결함 패턴 8종을 구분하는 CNN 기반 딥러닝 모델을 만들었습니다. 웨이퍼 단위로 무작위로 섞어서 Train/Test한 성능을 그대로 믿기보다, 학습에 쓰이지 않은 lot에서도 통하는지 따로 확인해봤습니다.

Problem

프로젝트 목적

웨이퍼 한 장에는 수백~수천 개의 칩(다이)이 배열되어 있고, 검사 후 "이 칩은 정상/불량"이라는 결과가 웨이퍼 전체를 하나의 지도(맵)처럼 나타냅니다. 불량 칩들은 무작위로 흩어지기보다 특정 공간 패턴을 형성하는 경우가 많으며, 이러한 패턴은 공정·장비 이상 원인의 후보를 좁히는 단서로 활용될 수 있습니다. 예를 들어 가장자리 집중 패턴은 정렬·공정 균일도 문제와, 선형 패턴은 이송·접촉 과정의 손상과 연관될 가능성이 있습니다. 이 프로젝트의 목표는 이러한 패턴을 사람이 일일이 판별하는 대신 웨이퍼맵을 보고 자동으로 분류하는 모델을 만드는 것입니다.

특정 결함 패턴이 없는 none 1종 + 결함 패턴 8종의 실제 웨이퍼맵 예시

Process

진행 흐름 — 9단계

각 단계는 이전 단계 평가 방식의 한계(선택 편향, lot 누수 등)를 하나씩 찾아 보완해나가는 순서로 구성되어 있습니다.

1

EDA — 데이터 분포와 편향 확인

라벨 비율 · 클래스 불균형 · 웨이퍼 크기 편차 파악

본격적으로 모델을 만들기 전에, 데이터의 분포와 편향부터 먼저 점검했습니다.

  • 라벨 있는 데이터는 전체 81만 장 중 17만 장(21.3%)뿐
  • 무패턴(none)이 147,431장으로 85% 차지, 가장 희귀한 Near-full은 149장(0.09%) — 최대 1,000배 클래스 불균형
  • 웨이퍼맵 크기가 346가지로 제각각

클래스 분포 — none이 워낙 많아서 나머지 8종은 로그 스케일로 봐야 겨우 비교가 됩니다.

→ 크기 통일과 클래스 불균형 대응이 요구됨

2

전처리 — 크기를 어떻게 통일했는가

범주형 값을 보존하며 이미지 크기 통일

EDA에서 확인한 크기 편차 때문에 이 상태로는 학습이 되지 않아서(CNN은 고정 크기 입력이 필요), 크기를 통일하는 전처리를 진행했습니다.

  • 0=칩 없음, 1=정상, 2=불량을 뜻하는 범주형 값 보존이 관건 — 일반적인 보간 방식으로 Re-size하면 값이 뭉개짐
  • 최근접 이웃(nearest-neighbor) 방식으로 64×64 Re-size
  • 클래스당 최대 2,000장 상한 → 학습셋 12,763장 구성
3

기본 CNN — 첫 결과와 약점 발견

9개 클래스(무패턴 + 결함 패턴 8종) 분류

전처리를 마친 데이터로 우선 기본적인 CNN을 학습시켜 baseline 성능과 약점을 확인했습니다.

  • 작은 CNN(합성곱 3층)을 CPU로 15 epoch 학습 — Macro F1 0.80, Accuracy 80.1%
  • Edge-Ring(F1 0.95), Center(F1 0.93) 등 모양이 뚜렷한 클래스는 F1 높음
  • Scratch만 F1 0.37로 낮음 — none·Loc과 혼동 다수 발생

혼동행렬 — Scratch가 none이나 Loc으로 자주 잘못 분류됩니다.

→ Scratch를 별도로 개선할 필요성 확인

4

도메인 파생특징 — Scratch F1 개선

원본 맵의 공간정보로 CNN 보완

Scratch는 결함 픽셀이 넓게 흩어져 있어 밀도만 보면 무패턴(none)과 큰 차이가 없고, 이 때문에 CNN이 밀도 기반 패턴만으로는 구분하기 어렵다는 것을 확인해서, 원본 이미지의 공간정보(위치·분포 형태)를 담은 파생특징을 추가했습니다.

  • Scratch 결함밀도 10.1% vs 무패턴(none) 10.6% — 밀도만으로는 구분이 거의 안 됨
  • 원본 해상도에서 계산한 파생특징 8개(불량 밀도, 중심으로부터 거리, 행·열 집중도 등)를 CNN에 함께 입력
지표CNN만CNN + 파생특징
Macro F10.7900.844
Scratch F10.3690.596

→ 개선 확인: Macro F1 0.790→0.844, Scratch F1 0.369→0.596

5

데이터 증강 — Scratch F1을 한 번 더 개선

회전 · 반전으로 소수 클래스 표본 다양성 보완

파생특징으로 어느 정도 개선했지만 Scratch는 표본 수 자체가 적어서, 회전·반전으로 데이터를 증강해 한 번 더 보완했습니다.

  • 회전·반전해도 결함 종류는 그대로 유지된다는 점을 이용해 표본이 적은 클래스 5개에 최대 8배 증강 적용
  • 증강은 train 쪽에만, 분할 이후에만 적용 — 분할 전에 하면 같은 웨이퍼의 증강 사본이 train과 test에 같이 들어가는 누수가 생김

→ 개선 확인: Scratch F1 0.61→0.75

이 증강은 어디까지나 "결함 유형을 구분"하는 게 목표일 때 유효합니다. 회전·반전을 적용하면 웨이퍼의 원래 방향 정보가 사라지므로, 결함 위치와 설비 방향의 관계처럼 방향 자체가 의미를 갖는 분석에는 이 데이터를 쓰면 안 됩니다.
6

lot 순서별 분포 이동 확인

lot 식별자 기준 독립 분할로 재평가

제조 데이터는 시간이 지나며 공정 조건이 바뀌는 경우가 흔한데, 지금까지는 전부 웨이퍼 단위 무작위 분할로 train/test해서 시간 변화에 따른 영향을 확인하지 못했습니다. 그래서 lot 번호 순서를 생산 순서의 대용값으로 삼아, 실제로 이런 분포 이동이 있는지부터 점검했습니다.

  • lot 번호(lot1, lot2, ...)는 실제 생산 시점을 보장하는 값은 아니지만, 번호순으로 확인한 결과 초반 1~2구간의 불량률이 51%로 나머지 구간(3~10%)보다 뚜렷하게 높음
  • 같은 lot이 train과 test에 걸치지 않도록 고유 lot 순서 기준으로 앞 80%/뒤 20%를 나눠 재평가

→ Macro F1 0.844→0.603으로 하락. 웨이퍼 단위 무작위 분할에서는 이런 구간별 편차가 train/test에 고르게 섞여 들어가 드러나지 않았던 것이고, 이는 실제 운영 환경(새 lot이 순서대로 들어오는 상황)을 제대로 반영하지 못하고 있었다는 의미입니다.

7

모델 선택과 최종 평가 분리

Train / Val / Test 3-way 분리 + 신뢰구간

지금까지는 여러 실험 중 가장 좋은 조합(파생특징+증강)을 그대로 최종 성능처럼 봤는데, 이 방식 자체가 선택 편향을 만들 수 있어서 평가 절차를 다시 분리했습니다.

  • 네 조합(파생특징×증강)을 같은 test set에서 비교해 제일 높은 걸 그대로 최종 성능으로 보고하면, test set을 모델 고르는 데도 쓴 셈이라 수치가 부풀려질 수 있음
  • train(60%)/validation(20%)/test(20%)로 분리 — validation에서만 조합을 고르고 test는 딱 한 번만 평가

→ 파생특징+증강 조합이 제일 우수 (Macro F1 0.885, 95% CI 0.868~0.900)

이 분할도 웨이퍼 단위 무작위 분할이라, 같은 lot의 웨이퍼가 train과 test에 함께 섞여 들어갈 수 있습니다. 즉 0.885는 "같은 분포 안에서의 성능"이고, 학습에 쓰이지 않은 lot에서의 성능은 아직 확인된 게 아닙니다.
8

lot 기준 3-way 독립 평가

핵심 결과

진짜 "학습에 쓰이지 않은 lot holdout" 성능 측정

웨이퍼 단위 무작위 분할로 확인한 성능(0.885)을 그대로 실제 운영 기대치로 쓰면 안 된다는 걸 6·7단계에서 알아냈으니, 이번엔 lot 단위로 나눠 학습에 쓰이지 않은 lot을 test로 사용해 성능을 측정했습니다.

  • 6단계는 lot 기준으로 train/test만 나눈 2-way였고, 여기서는 validation까지 포함한 3-way를 lot 기준으로 적용해 모델 선택 편향과 lot 누수를 동시에 제거
  • 고유 lot을 60/20/20으로 분리 — validation(학습에 쓰이지 않은 lot)에서 조합을 고르고 test lot에서 딱 한 번만 평가
평가 방식Macro F1의미
웨이퍼 단위 무작위 3-way (7단계)0.885같은 분포에서 패턴을 얼마나 잘 배우는가

  • 신뢰구간(0.695~0.746)은 같은 lot 안 웨이퍼끼리는 서로 독립이 아닐 수 있다는 걸 감안해 lot 단위 cluster bootstrap으로 계산

→ 실제 운영에서 기대할 성능은 0.885가 아니라, 학습에 쓰이지 않은 lot 기준으로 측정한 0.721에 더 가깝다고 보는 게 맞습니다.

9

모델의 공간적 반응 확인 (Grad-CAM)

CNN이 실제로 어디를 보고 판단했는가

수치로는 성능을 확인했으니, 마지막으로 모델이 실제로 어디를 보고 판단하는지 Grad-CAM으로 확인했습니다.

  • 최종 모델은 이미지를 보는 CNN 경로와 파생특징 8개를 보는 경로를 각각 계산한 뒤 합쳐서 분류하는 구조라 "하이브리드 모델"이라고 부름
  • Random·Near-full·Loc·Edge류는 CNN이 대체로 실제 결함 위치를 보고 판단
  • Scratch는 선 전체가 아니라 한 지점에만 국소적으로 반응하는 경우가 많음
다만 Grad-CAM은 CNN 이미지 경로만 보여줍니다. 파생특징 경로가 판단에 얼마나 기여했는지는 이 히트맵으로는 알 수 없습니다.

Highlights

프로젝트 핵심 역량

  • EDA 기반 문제 정의 — 라벨 결측, 최대 약 1,000배 클래스 불균형, 웨이퍼맵 크기 편차를 먼저 파악
  • 도메인 특징 설계와 통제 실험 — 원본 해상도 기반 파생특징과 증강을 설계하고 2×2 ablation으로 효과를 분리 검증
  • 제조 데이터에 맞춘 평가 설계 — 웨이퍼 단위 무작위 분할과 lot 단위 독립 분할을 구분하고, validation 기반 모델 선택과 최종 test 평가를 분리
  • 불확실성 정량화 — lot-cluster bootstrap으로 동일 lot 내 상관을 반영한 신뢰구간 계산
  • 검증 코드 자체의 재점검 — lot 경계 누수 버그를 스스로 찾아 고유 lot 기준 분할로 수정, 그 전후 수치를 투명하게 공개
Honesty

한계점

  • CPU 환경 제약으로 클래스당 최대 2,000장만 사용 — 전체 데이터·GPU 학습 시 추가 개선 여지
  • Scratch F1(0.60~0.78)이 다른 클래스 대비 여전히 낮고, Grad-CAM에서도 모델이 선 전체보다 국소 단서에 반응하는 경향이 확인됨
  • 학습에 쓰이지 않은 lot holdout 성능(0.721)은 웨이퍼 단위 무작위 train/test 성능(0.885)보다 확실히 낮아, 학습에 쓰이지 않은 lot 일반화가 보장되지 않음
  • lot 번호는 실제 타임스탬프가 아니므로, 0.721을 미래 시점에 대한 완전한 시간 외삽 성능으로 해석하지 않음
  • lot 구간별 분포 차이가 실제 공정 변화 때문인지 라벨링 정책 때문인지는 메타데이터만으로 확정 불가
