WM-811K 웨이퍼맵 결함 패턴 분류

웨이퍼맵 이미지 17만 장으로 정상 1종·결함 8종을 자동 분류하는 CNN을 만들고, "무작위로 나눠서 평가한 성능"과 "실제로 본 적 없는 새 lot에서의 성능"을 구분해서 검증한 프로젝트입니다.

이 프로젝트가 푸는 문제

웨이퍼 한 장에는 수백~수천 개의 칩이 배열되고, 검사 후 불량 칩의 위치가 웨이퍼 전체를 하나의 지도(맵)처럼 보여줍니다. 불량은 무작위로 흩어지기보다 특정 공간 패턴을 형성하는 경우가 많고, 이 패턴은 공정·장비 이상의 원인을 좁히는 단서가 됩니다 — 가장자리 집중은 정렬 문제와, 선형 패턴은 이송 중 손상과 연관될 수 있습니다. 이 패턴을 사람이 일일이 판별하는 대신 이미지를 보고 자동으로 분류하는 모델을 만드는 것이 목표입니다.

진행 흐름

9단계로 진행했고, 뒤로 갈수록 "이 성능이 정말 믿을 만한가"를 점점 더 엄격하게 되묻는 구조입니다.

1EDA — 데이터의 함정부터 확인

라벨 비율, 클래스 불균형, 웨이퍼 크기 편차 파악

전체 81만 장 중 라벨이 붙은 건 17만 장(21.3%)뿐입니다. 그중에서도 정상(none)이 147,431장(85%)인 반면 가장 희귀한 Near-full은 149장(0.09%) — 클래스 간 비율 차이가 약 1,000배에 달합니다. 웨이퍼맵 크기도 346가지로 제각각이라 통일이 필요했습니다.

클래스 분포 — none이 압도적으로 많고 나머지 8종은 로그 스케일로 봐야 겨우 비교됩니다.

2전처리 — 크기를 어떻게 통일했는가

범주형 값을 보존하며 이미지 크기 통일

웨이퍼맵은 "0=칩 없음, 1=정상, 2=불량"이라는 범주형 값이라, 사진처럼 부드럽게 리사이즈하면 값이 뭉개집니다. 최근접 이웃(nearest-neighbor) 방식으로 64×64로 통일해 범주형 값을 그대로 보존했고, 클래스당 최대 2,000장 상한을 둬 학습셋(12,763장)을 구성했습니다.

3기본 CNN — 첫 결과와 약점 발견

9개 클래스(정상 + 결함 8종) 분류

작은 CNN(합성곱 3층)을 CPU에서 학습시킨 결과 Macro F1 0.80, Accuracy 80.1%. Edge-Ring(0.95)·Center(0.93)는 잘 맞혔지만, Scratch는 F1 0.37로 유독 낮았습니다.

혼동행렬 — Scratch가 none·Loc과 자주 혼동됩니다.

4도메인 파생특징 — 왜 Scratch만 어려운가

원본 맵의 공간정보로 CNN 보완

원인을 파고드니 Scratch의 불량 칩 비율(10.1%)이 정상 웨이퍼(10.6%)보다 낮았습니다 — 가늘고 긴 선이라 불량 칩 수 자체가 적고, 64×64 축소 과정에서 그 선이 뭉개진 겁니다. 원본 해상도에서 계산한 8개 파생특징(불량 밀도, 중심 거리, 행·열 집중도 등)을 CNN에 더했습니다.

5데이터 증강 — Scratch를 한 번 더 개선

회전·반전으로 소수 클래스 표본 다양성 보완

회전해도 뒤집어도 결함 종류는 유지된다는 성질을 이용해, 표본이 적은 5개 클래스에 최대 8배 증강을 적용했습니다 (train 분할 이후에만 적용해 데이터 누수 방지). Scratch F1이 0.61 → 0.75로 다시 한번 크게 올랐습니다.

참고: 이 증강은 "결함 유형 분류"만을 목표로 합니다. 웨이퍼 방향이 진단에 의미를 갖는 다른 목적(장비 방향과 결함의 상관관계 분석 등)에는 적절하지 않을 수 있습니다.

6lot 분포 이동 위험 점검

lot 식별자 기준 독립 분할로 재평가

지금까지는 전부 무작위 분할로 평가했는데, 제조 데이터는 시간에 따라 조건이 바뀌는 게 흔합니다. lot 번호(lot1, lot2, ...)를 생산 순서의 대용값으로 써서 확인해보니, 초반 20% lot 구간의 불량률이 약 51%, 나머지 구간은 3~10%로 극단적으로 달랐습니다.

같은 lot이 train/test에 걸치지 않도록 고유 lot 기준으로 앞 80%/뒤 20%를 나눠 재평가하니, Macro F1이 0.844 → 0.603으로 뚝 떨어졌습니다 — 무작위 분할이 성능을 낙관적으로 보여줄 수 있다는 첫 증거였습니다.

7모델 선택과 최종 평가 분리

Train/Val/Test 3-way 분리 + 신뢰구간

기존엔 4개 조합(파생특징×증강)을 같은 test set에서 비교하고 최고점을 그대로 "최종 성능"이라 보고했는데, 이건 test set을 모델 선택에도 쓴 셈이라 선택 편향 위험이 있습니다. train(60%)/validation(20%)/test(20%)로 나눠 validation에서만 조합을 고르고, test는 딱 한 번만 평가하도록 재구성했습니다.

결과: Macro F1 0.885 (95% CI 0.868~0.900) — 파생특징+증강 조합, 선택 편향을 제거한 수치.

다만 이 분할은 웨이퍼 단위 무작위 분할이라, 같은 lot이 train/val/test에 섞일 수 있습니다. 즉 0.885는 "같은 분포에서의 성능"이지 "미관측 lot 일반화 성능"이 아닙니다.

8lot 기준 3-way 독립 평가 핵심 결과

진짜 "미관측 lot holdout" 성능 측정

6단계(lot 기준 분할)와 7단계(모델 선택/평가 분리)의 장점을 합쳤습니다. 고유 lot을 60%/20%/20%로 나누고, validation(미관측 lot)에서 조합을 고른 뒤 test(더 새로운 lot)에서 딱 한 번 평가했습니다.

평가 방식Macro F1의미
웨이퍼 무작위 3-way (7단계)0.885같은 분포에서 패턴을 얼마나 잘 배우는가
lot 2-way (6단계)0.603모델 고정 후 거친 진단
lot 3-way (8단계)0.721선택 편향 없이 측정한 공식 대표 수치

신뢰구간(0.695~0.746)은 같은 lot 안 웨이퍼가 서로 독립이 아닐 수 있다는 점을 반영해 lot 단위 cluster bootstrap으로 계산했습니다. 실전 배포 성능을 제시한다면 0.885가 아니라 0.721을 "신규 생산 배치에서 기대할 수 있는 성능"으로 보고하는 것이 정직합니다.

9모델의 공간적 반응 확인 (Grad-CAM)

CNN이 실제로 어디를 보고 판단했는가

점수가 좋다고 모델이 항상 올바른 이유로 맞힌다는 보장은 없습니다. Grad-CAM으로 확인한 결과, Random·Near-full·Loc·Edge류는 각 패턴 정의와 대체로 일치하는 위치에 반응했지만, Scratch는 선 전체가 아니라 국소적인 지점에만 반응하는 경향이 관찰됐습니다.

한계: 최종 모델은 CNN(이미지)과 파생특징이 결합된 하이브리드 구조입니다. Grad-CAM은 CNN 경로만 설명하므로, 파생특징이 판단에 기여한 부분은 이 히트맵에 나타나지 않습니다.

포트폴리오 핵심 역량

  • EDA 기반 문제 정의: 라벨 결측, 최대 약 1,000배 클래스 불균형, 웨이퍼맵 크기 편차를 먼저 파악
  • 도메인 특징 설계와 통제 실험: 원본 해상도 기반 파생특징과 증강을 설계하고 2×2 ablation으로 효과를 분리 검증
  • 제조 데이터에 맞춘 평가 설계: 웨이퍼 무작위 분할과 lot 단위 독립 분할을 구분하고, validation 기반 모델 선택과 최종 test 평가를 분리
  • 불확실성 정량화: lot-cluster bootstrap으로 동일 lot 내 상관을 반영한 신뢰구간 계산
  • 검증 코드 자체의 재점검: lot 경계 누수 버그를 스스로 찾아 고유 lot 기준 분할로 수정, 그 전후 수치를 투명하게 공개

정직하게 남겨둔 한계

  • CPU 환경 제약으로 클래스당 최대 2,000장만 사용 — 전체 데이터·GPU 학습 시 추가 개선 여지
  • Scratch F1(0.60~0.78)이 다른 클래스 대비 여전히 낮고, Grad-CAM에서도 모델이 선 전체보다 국소 단서에 반응하는 경향이 확인됨
  • 미관측 lot holdout 성능(0.721)은 동일 분포 성능(0.885)보다 확실히 낮아, 신규 lot 일반화가 보장되지 않음
  • lot 번호는 실제 타임스탬프가 아니므로, 0.721을 미래 시점에 대한 완전한 시간 외삽 성능으로 해석하지 않음
  • lot 구간별 분포 차이가 실제 공정 변화 때문인지 라벨링 정책 때문인지는 메타데이터만으로 확정 불가
