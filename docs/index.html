Problem

프로젝트 목적

웨이퍼 한 장에는 칩(다이)이 수백~수천 개 배열돼 있고, 검사가 끝나면 정상/불량 결과가 웨이퍼 전체를 하나의 지도처럼 보여줍니다. 불량은 무작위로 흩어지기보다 특정 공간 패턴을 이루는 경우가 많은데, 이 패턴이 원인을 좁히는 단서가 됩니다. 가장자리에 몰리면 정렬 문제를, 선 모양이면 이송 중 손상을 의심해볼 수 있는 식입니다. 사람이 하나씩 눈으로 판별하는 대신, 이미지를 보고 자동으로 분류하는 모델을 만드는 것이 목표였습니다.

Process

진행 흐름 — 9단계

뒤로 갈수록 "이 성능이 정말 믿을 만한가"를 점점 더 엄격하게 되묻는 구조입니다.

1

EDA — 데이터의 함정부터 확인

라벨 비율 · 클래스 불균형 · 웨이퍼 크기 편차 파악

전체 81만 장 중 라벨이 붙은 건 17만 장, 21.3%뿐이었습니다. 그마저도 정상(none)이 147,431장으로 85%를 차지하고, 가장 희귀한 Near-full은 149장(0.09%)이라 둘 사이 비율 차이가 거의 1,000배였습니다. 웨이퍼맵 크기도 346가지나 돼서 모델에 넣기 전에 이것부터 정리해야 했습니다.

클래스 분포 — none이 워낙 많아서 나머지 8종은 로그 스케일로 봐야 겨우 비교가 됩니다.

2

전처리 — 크기를 어떻게 통일했는가

범주형 값을 보존하며 이미지 크기 통일

0은 칩 없음, 1은 정상, 2는 불량을 뜻하는 범주형 값이라, 사진처럼 부드럽게 리사이즈하면 값이 뭉개집니다. 그래서 최근접 이웃(nearest-neighbor) 방식으로 64×64에 맞췄고, 클래스당 최대 2,000장 상한을 둬서 학습셋 12,763장을 구성했습니다.

3

기본 CNN — 첫 결과와 약점 발견

9개 클래스(정상 + 결함 8종) 분류

작은 CNN(합성곱 3층)을 CPU로 15 epoch 돌렸더니 Macro F1 0.80, Accuracy 80.1%가 나왔습니다. Edge-Ring(0.95)이나 Center(0.93)처럼 모양이 뚜렷한 건 잘 맞혔는데, Scratch만 F1 0.37로 유독 안 됐습니다.

혼동행렬 — Scratch가 none이나 Loc으로 자주 잘못 분류됩니다.

4

도메인 파생특징 — 왜 Scratch만 어려운가

원본 맵의 공간정보로 CNN 보완

왜 그런가 들여다보니 Scratch의 불량 칩 비율(10.1%)이 오히려 정상 웨이퍼(10.6%)보다 낮았습니다. 선이 가늘고 길다 보니 불량 칩 수 자체가 적고, 64×64로 줄이는 과정에서 그 선마저 뭉개진 거였습니다. 그래서 원본 해상도에서 직접 계산한 파생특징 8개(불량 밀도, 중심으로부터 거리, 행·열 집중도 등)를 CNN에 같이 넣어봤습니다.

5

데이터 증강 — Scratch를 한 번 더 개선

회전 · 반전으로 소수 클래스 표본 다양성 보완

회전시키거나 뒤집어도 결함 종류는 그대로 유지된다는 점을 이용해서, 표본이 적은 클래스 5개에 최대 8배 증강을 적용했습니다. train 쪽에만, 그것도 분할 이후에만 적용해서 누수는 막았습니다. Scratch F1이 0.61에서 0.75로 한 번 더 올랐습니다.

이 증강은 어디까지나 "결함 유형을 구분"하는 게 목표일 때 유효합니다. 웨이퍼 방향 자체가 의미 있는 분석(장비 방향과 결함의 상관관계 같은)에는 맞지 않을 수 있습니다.
6

lot 분포 이동 위험 점검

lot 식별자 기준 독립 분할로 재평가

지금까지는 다 무작위로 섞어서 평가했는데, 제조 데이터는 시간이 지나면서 공정 조건이 바뀌는 일이 흔합니다. lot 번호(lot1, lot2, ...)를 생산 순서 대신 써서 확인해보니, 초반 20% lot 구간의 불량률이 51%였고 나머지는 3~10%대였습니다. 거의 다른 데이터처럼 보일 정도였습니다.

같은 lot이 train과 test에 걸치지 않게 고유 lot 기준으로 앞 80%/뒤 20%를 나눠서 다시 평가했더니, Macro F1이 0.844에서 0.603으로 뚝 떨어졌습니다. 무작위 분할만 믿고 있었으면 몰랐을 결과입니다.

7

모델 선택과 최종 평가 분리

Train / Val / Test 3-way 분리 + 신뢰구간

원래는 네 조합(파생특징×증강)을 같은 test set에서 비교하고 제일 높은 걸 그대로 최종 성능이라 보고했는데, 생각해보니 이건 test set을 모델 고르는 데도 쓴 셈이라 점수가 부풀려질 수 있는 구조였습니다. 그래서 train(60%)/validation(20%)/test(20%)로 나눠서, validation에서만 조합을 고르고 test는 딱 한 번만 평가하도록 다시 짰습니다.

결과는 Macro F1 0.885(95% CI 0.868~0.900) — 파생특징+증강 조합이고, 선택 편향을 걷어낸 수치입니다.

다만 이 분할도 웨이퍼를 무작위로 섞은 거라, 같은 lot이 train/val/test에 다 섞여 들어갈 수 있습니다. 그러니까 0.885는 "같은 분포 안에서의 성능"이지, 미관측 lot에서의 성능은 아직 모릅니다.
8

lot 기준 3-way 독립 평가

핵심 결과

진짜 "미관측 lot holdout" 성능 측정

6단계(lot 기준 분할)와 7단계(모델 선택/평가 분리)를 합쳤습니다. 고유 lot을 60/20/20으로 나누고, validation(미관측 lot)에서 조합을 고른 다음 test lot에서 딱 한 번만 평가했습니다.

평가 방식Macro F1의미
웨이퍼 무작위 3-way (7단계)0.885같은 분포에서 패턴을 얼마나 잘 배우는가
lot 2-way (6단계)0.603모델 고정 후 거친 진단
lot 3-way (8단계)0.721선택 편향 없이 측정한 공식 대표 수치

신뢰구간(0.695~0.746)은 같은 lot 안 웨이퍼끼리는 서로 독립이 아닐 수 있다는 걸 감안해서 lot 단위 cluster bootstrap으로 계산했습니다. 실제로 배포한다면 0.885가 아니라 0.721을 "이 모델이 새 생산 배치에서 낼 수 있는 성능"으로 말하는 게 맞다고 생각합니다.

9

모델의 공간적 반응 확인 (Grad-CAM)

CNN이 실제로 어디를 보고 판단했는가

점수가 좋다고 모델이 항상 맞는 이유로 맞히는 건 아니라서, Grad-CAM으로 실제로 어디를 보고 판단했는지 확인해봤습니다. Random·Near-full·Loc·Edge류는 대체로 패턴 정의와 맞는 위치에 반응했는데, Scratch는 선 전체가 아니라 한 지점에만 반응하는 경우가 많았습니다.

다만 최종 모델은 CNN과 파생특징을 같이 쓰는 구조라, Grad-CAM은 CNN 쪽 경로만 보여줍니다. 파생특징이 얼마나 기여했는지는 이 히트맵으로는 알 수 없습니다.

Highlights

포트폴리오 핵심 역량

  • EDA 기반 문제 정의 — 라벨 결측, 최대 약 1,000배 클래스 불균형, 웨이퍼맵 크기 편차를 먼저 파악
  • 도메인 특징 설계와 통제 실험 — 원본 해상도 기반 파생특징과 증강을 설계하고 2×2 ablation으로 효과를 분리 검증
  • 제조 데이터에 맞춘 평가 설계 — 웨이퍼 무작위 분할과 lot 단위 독립 분할을 구분하고, validation 기반 모델 선택과 최종 test 평가를 분리
  • 불확실성 정량화 — lot-cluster bootstrap으로 동일 lot 내 상관을 반영한 신뢰구간 계산
  • 검증 코드 자체의 재점검 — lot 경계 누수 버그를 스스로 찾아 고유 lot 기준 분할로 수정, 그 전후 수치를 투명하게 공개
Honesty

정직하게 남겨둔 한계

  • CPU 환경 제약으로 클래스당 최대 2,000장만 사용 — 전체 데이터·GPU 학습 시 추가 개선 여지
  • Scratch F1(0.60~0.78)이 다른 클래스 대비 여전히 낮고, Grad-CAM에서도 모델이 선 전체보다 국소 단서에 반응하는 경향이 확인됨
  • 미관측 lot holdout 성능(0.721)은 동일 분포 성능(0.885)보다 확실히 낮아, 신규 lot 일반화가 보장되지 않음
  • lot 번호는 실제 타임스탬프가 아니므로, 0.721을 미래 시점에 대한 완전한 시간 외삽 성능으로 해석하지 않음
  • lot 구간별 분포 차이가 실제 공정 변화 때문인지 라벨링 정책 때문인지는 메타데이터만으로 확정 불가
